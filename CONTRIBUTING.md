# Contributing to Aelyx-Work projects

## Before opening a pull request

- Check the repository README for its language, framework, and local development instructions.
- Create a focused branch and keep the change small enough to review.
- Add or update tests when behavior changes. Run the repository's lint, test, and build commands when configured.
- Update documentation or configuration examples when the change affects how people use or deploy the project.
- Never commit passwords, API keys, customer data, or production configuration.

## Pull requests

Describe the problem and the change, list the checks you ran, and call out any deployment or data migration considerations. For user interface changes, include a screenshot or short recording when it helps reviewers.

Review and merge policies may vary by repository. Follow the repository's current settings and maintainers' guidance.
